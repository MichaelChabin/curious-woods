# Seeds

One idea, one file. Facets on top, prose below. The facet values are closed and live
in `00-FOUNDATION/Facet-Vocabulary.md` — read that before writing a seed.

Seeds replace `99-IDEAS/`, which was flat and therefore rotted. The difference is not
tidiness. A flat list holds the connections in Michael's head; a faceted one holds them
in the file, where Claude Code and every future chat can traverse them.

**Naming:** `kebab-case-descriptive.md`. Era in the name only when the era *is* the
idea (`montparnasse-11895.md`).

**Writing one costs a minute.** Facets, one paragraph, done. A seed does not need to be
good, resolved, or connected to anything. Getting it out of your head is the entire job.

**Queries this makes possible** — the reason for the discipline:

- *What else was happening then?* → `era` within a range
- *What serves this intuition?* → `intuitions` contains `i11`
- *What hangs on temperature?* → `scale` contains `temperature`
- *What does this Lab still owe?* → `lab` is `perception` and `status` is `seed`
- *What is warm and could be picked up today?* → `status` is `warm`

In Obsidian these are Dataview or Bases views and update themselves. Nobody maintains
a list of what's related to 1895. You ask.

**Seeds are not the board.** `00-BOARD.md` holds what is moving. A seed becomes a board
item when it gets a next action; the seed file stays where it is and its status changes.
